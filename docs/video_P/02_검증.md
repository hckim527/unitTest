### 측정 환경 함정 (TSQA 기대값 고정 시 주의)

1. **공유 탭/오염된 컨텍스트에서는 결과가 뒤집힌다.** 같은 프로필에서 반복 측정하면 media engagement 누적으로 소리 있는 video 도 자동 재생되는 경우가 관측되었다(무음 offscreen 은 차단, 유음은 재생 등 정반대 조합). **반드시 신규 컨텍스트에서 측정**할 것.

### 판정 근거 구성 (audio 계열과의 차이)

- `audio` 는 controls 미설정 시 UA 스타일(`audio:not([controls]){display:none}`)로 요소가 **0 x 0 / 표시 안 됨** 이라 렌더 영역 크기로 컨트롤 표시 여부를 구분할 수 있었다.
- **`video` 는 controls 유무와 무관하게 렌더 영역이 동일(250 x 141, `display:block`)** 하다. 따라서 크기만으로 컨트롤 표시 여부를 판정할 수 없어, **`getAttribute('controls')` / `el.controls` 를 주 근거**로 두고 `getBoundingClientRect()` 는 보조 출력으로만 사용했다. (`nShownCount` 도 audio 의 `height > 0` 이 아니라 `el.controls === true` 기준)
- 브라우저 기본 컨트롤은 shadow DOM 이라 내부 재생/일시정지 버튼·볼륨바 DOM 직접 조회는 불가 — `@spec` 2 를 validation 으로 만들지 않은 사용자 지시와 일치.

- 실측: **둘 다 `true`** (target5 도 자동 재생됨).
- 원인 확인용 통제 실험 (모두 동일 결과 = target5 재생됨):
  1. MCP 연결 브라우저 `newContext` (1400x950 / 1280x800)
  2. `browserType.launch({headless:true, channel:'chrome'})` **완전 신규 브라우저(신규 임시 프로필)**
  3. 위 + `ignoreDefaultArgs:['--autoplay-policy=no-user-gesture-required']`
  4. **headed 실제 Chrome** + 위 flag 제거
- 같은 브라우저(3번 조건)에서 **기존 `video_P_autoplay_1.xml` 도 재측정** → target1/target2(소리 있음, muted 없음)가 `currentTime=1.98, ended=true` 로 **자동 재생됨**. 즉 02_검증.md 상단(autoplay 절)에 기록된 "차단" 실측은 **현재 이 환경에서 재현되지 않음** → 샘플 구성 문제가 아니라 **브라우저 자동 재생 정책 환경 차이**.
- 오디오 트랙 존재는 확인됨: `#target5` 의 `webkitAudioDecodedByteCount = 5740` (소리 포함 파일 맞음).
- `navigator.getAutoplayPolicy` 는 이 브라우저에서 미지원(`unsupported`).
- 가이드 문구가 "자동 재생이 **허용될 수 있습니다**" 이므로 target4=true 는 문구와 일치하며, target5 의 재생은 브라우저가 차단하지 않은 환경 특성. **엔진 결함 아님**.

### MCP 실측값 (engine R1641, port 49920, HeadlessChrome, 재생 시작 전 측정)

| 항목 | target1 (`preload="auto"`) | target2 (`preload=""`) | target3 (`preload="metadata"`) | target4 (`preload="none"`) | target5 (속성 없음) |
|---|---|---|---|---|---|
| `getAttribute("preload")` | `"auto"` | `""` | `"metadata"` | `"none"` | `null` |
| `hasAttribute("preload")` | true | true | true | true | **false** |
| `el.preload` (정규화값) | `auto` | **`auto`** | `metadata` | `none` | **`metadata`** |
| `readyState` | 4 | 4 | 4 | **0** | 4 |
| `networkState` | 1 | 1 | 1 | 1 | 1 |
| `buffered.length` | 1 | 1 | 1 | **0** | 1 |
| `duration` | 1.975124 | 1.975124 | 1.975124 | **null** | 1.975124 |
| `videoWidth x videoHeight` | 320x180 | 320x180 | 320x180 | **0x0** | 320x180 |

- **`none` 대비 성립**: `preload="none"` 만 재생 전 `readyState=0` / `buffered.length=0` / `duration=null` / `videoWidth=0` → 데이터를 전혀 내려받지 않음. 나머지 4개는 `readyState=4` / `buffered=1`.
- **빈 문자열 정규화**: `getAttribute` 는 `""` 이지만 IDL `el.preload` 가 `auto` → 가이드의 "빈 문자열 설정 시 auto 로 동작" 그대로 확인.
- **미설정 정규화**: 속성 없는 target5 의 `el.preload` 는 브라우저 기본값 `metadata`(Chrome) → 속성 제거 시 설정 해제 확인.
- **`auto` vs `metadata` 는 버퍼링 상태로 구분되지 않음**(둘 다 `readyState=4`, `buffered=1`). 파일이 약 18KB 로 매우 작아 브라우저가 힌트와 무관하게 전체를 내려받음. `@spec` 1("실제 동작은 브라우저의 HTML5 video 처리에 따라 결정")에 부합하므로 결함 아님. audio(32KB) 실측과 동일 양상.
