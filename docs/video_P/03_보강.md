#### `@spec` 1 vs 미설정본 실측 대조 (결과 불일치)

- `@spec` 1 은 "필수 속성으로 함께 정의되므로 컨트롤이 **항상** 표시된다" 고 규정.
- 실측: `controls` 속성을 정의하지 않은 `target3` 은 `getAttribute('controls')=null`, `el.controls=false` → **기본 재생 컨트롤 미표시** (컨트롤 표시 video 2 / 3).
- 즉 "항상 표시" 는 **컴포넌트 정의 시 controls 를 필수로 함께 넣는다는 전제** 위에서만 성립하며, 배포 엔진에 `video` uiplugin 이 없어 정적 `<video>` 가 raw HTML pass-through 로 처리되는 현재 구조에서는 **엔진이 controls 를 자동 부여하지 않는다**. 소스에서 속성을 빼면 컨트롤은 사라진다.
- audio 와의 차이: `audio` 는 controls 미설정 시 UA 스타일로 요소 자체가 `0 x 0` / 비표시였으나, **`video` 는 렌더 영역이 그대로 유지(250 x 141, `display:block`)** 되고 컨트롤 UI 만 사라진다. 따라서 표시 여부 판정의 주 근거는 속성/프로퍼티이고 렌더 영역 크기는 보조 근거로만 출력한다.

- `UT_01_생성.md` §7 적용: `wf_body_sample` 삭제 → `grp_sample > grp_comp` 직접 배치, 정적 `<video>` 3개(`id="target1"` / id 미설정 / `id="style"`). `comp_init`·Target 재생성 버튼 없음.

#### 판단 근거 / 제외
- **`@spec` 3 실측: 예약어(`style`) id 설정 시 오류 0건, id 는 `style` 그대로 렌더.** 가이드 원문이 "발생할 수 **있습니다**"(가능성) 이므로 문구를 그대로 유지하고 실측값을 출력. 정적 `<video>` 는 raw HTML pass-through 라 WebSquare 컴포넌트 레지스트리를 거치지 않아 예약어 충돌이 발생하지 않음(HTML5 시맨틱 6종·`audio` 실측과 동일).

- 배포 엔진(R1641)에 `video` uiplugin 부재 → 컴포넌트 객체/메소드 없음, `$p.dynamicCreate` 불가, 정적 선언 필수, id 에 `mf_` 미부여(`#target1` 직접 조회).
- `src` 는 컨텍스트 루트 절대경로(`/data/media/sample_clip.webm`) 필수.
- 가이드 문구와 실측 불일치 없음(`auto`/`metadata` 미구분은 `@spec` 1 범위 내).
