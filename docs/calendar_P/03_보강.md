# calendar Property 보강 대조표

## calendar_P_dayMoveFixed_1.xml

API: `WebSquare.uiplugin.calendar.dayMoveFixed`
설명: Calendar 컴포넌트에서 년/월을 탐색할때 변경되는 선택일의 일자를 유지할지 설정합니다.
기본값: false (`@default` 비어있음, `@propval` 의 false 가 default 표기)
조건: `calendarValueType=year,yearMonth` 이거나 `dateMoveFixed=true` 이면 동작하지 않음

| API 가이드 항목 | 샘플 validation | 케이스 / 검증 방법 | 상태 |
|---------------|---------------|----------------|------|
| @description: 년/월 탐색 시 변경되는 선택일의 일자를 유지할지 설정 | description 영역에 반영 | - | OK |
| @propval false (default): 이동된 년/월에 맞게 변경되는 선택일의 일자가 1일로 변경됨 | (1) "미설정(기본값 false) 시 ... 일자가 1일로 변경됩니다." / (4) "false 설정 시 ... 일자가 1일로 변경됩니다." | 이전월/다음월 탐색 후 getValue() 일자가 01 로 표시 | OK |
| @propval true: 이동된 년/월에 맞게 변경되는 선택일의 일자를 유지 | (2) "true 설정 시 ... 일자를 유지합니다." | dayMoveFixed=true + 초기 1/15 → 이전월/다음월 탐색 후 getValue() 일자 유지 | OK |
| @propval true: 이동된 월에 선택일의 일자가 없는 경우 마지막 일자가 선택됨 | (3) "true 설정 시 이동된 월에 선택일의 일자가 없는 경우 마지막 일자가 선택됩니다." | 초기 선택일을 1/31 로 설정 → 다음월(2월) 탐색 시 2/28 (또는 2/29) 로 자동 조정 | OK |
| @description: calendarValueType=year 이면 동작 안함 | (5) "calendarValueType=year 이면 dayMoveFixed 속성은 동작하지 않습니다." | con_calendarValueType=year + dayMoveFixed=true → 일자 유지 동작 무관 (year 모드는 일자 개념 없음) | OK |
| @description: calendarValueType=yearMonth 이면 동작 안함 | (6) "calendarValueType=yearMonth 이면 dayMoveFixed 속성은 동작하지 않습니다." | con_calendarValueType=yearMonth + dayMoveFixed=true → 일자 유지 동작 무관 (yearMonth 모드는 일자 개념 없음) | OK |
| @description: dateMoveFixed=true 이면 동작 안함 | (7) "dateMoveFixed=true 이면 dayMoveFixed 속성은 동작하지 않습니다. (dateMoveFixed 가 우선)" | con_dateMoveFixed=true + con_dayMoveFixed=true → dateMoveFixed 우선 적용, getValue() 일자가 유지되지 않거나 '00' 반환 | OK |
| @spec: 변경된 선택일은 팝업 달력의 날짜 영역과 하단의 선택일에 반영됨 | (8) "변경된 선택일은 팝업 달력의 날짜 영역과 하단의 선택일에 반영됩니다." | btn_getInfo 의 [현재 하단 선택일 표시] + [현재 반전 셀(선택일)] 출력 / 이전월/다음월 탐색 후 before→after 비교 | OK |
| @spec: calendarValueType=yearMonthDate, yearMonthDateHour 일때 팝업 달력 하단에 선택일이 표시됨 | (9) "calendarValueType=yearMonthDate, yearMonthDateHour 일때 팝업 달력 하단에 선택일이 표시됩니다." | con_calendarValueType=yearMonthDate / yearMonthDateHour → getCurrentDateText() 표시 / 그 외 → '(숨김)' 또는 '(currentDate DOM 없음)' | OK |
| @spec: 년/월 탐색 시 선택일 변경되면 onchange 이벤트 발생 | (10) "년/월을 탐색할때 선택일이 변경되면 onchange 이벤트가 발생합니다." | target1_onchange 핸들러에서 플래그 set, 이전월/다음월/이전년/다음년 탐색 후 onchange=발생 출력 | OK |
| @spec: 년/월 탐색 시 선택일 변경되면 onviewchange 이벤트 발생 | (11) "년/월을 탐색할때 선택일이 변경되면 onviewchange 이벤트가 발생합니다." | target1_onviewchange 핸들러에서 플래그 set, 이전월/다음월/이전년/다음년 탐색 후 onviewchange=발생 출력 | OK |
| @related: calendarValueType, dateMoveFixed, getValue(), onchange, onviewchange | (5),(6),(7),(10),(11) 에 모두 포함 | con_ 옵션 / 이벤트 핸들러 / btn_getInfo 의 getValue() 출력 | OK |

### 보강 체크리스트
- [x] API 가이드의 모든 @description 내용이 validation에 반영됨
- [x] 모든 @propval 값(true / false default)에 대한 validation 항목 존재
- [x] 동작하지 않는 조건(`calendarValueType=year`, `yearMonth`, `dateMoveFixed=true`) 각각 별도 validation 분리
- [x] @spec 의 모든 항목(날짜영역+하단 반영 / yearMonthDate,yearMonthDateHour 하단 표시 / onchange 발생 / onviewchange 발생) 별도 validation 분리
- [x] 마지막 일자 자동 조정(#3) 케이스를 위한 초기 선택일 20250131 설정
- [x] 이전월 / 다음월 / 이전년 / 다음년 4종 탐색 버튼 모두 제공 (년 단위 탐색에서도 dayMoveFixed 적용)
- [x] onchange / onviewchange 핸들러 등록 + 탐색 후 플래그 검사 로직

### 케이스 구성 (con_ 옵션 조합)
- 동적 con_ 조합:
  - con_dayMoveFixed: true / false
  - con_dateMoveFixed: true / false
  - con_calendarValueType: yearMonthDate / yearMonthDateHour / yearMonthDateTime / year / yearMonth
- 검증 시나리오:
  - dayMoveFixed=true + dateMoveFixed=false + calendarValueType=yearMonthDate + 초기 20250131 → 다음월 탐색 → 2/28 자동 선택 (#2, #3 검증)
  - dayMoveFixed=false + dateMoveFixed=false + calendarValueType=yearMonthDate + 초기 20250131 → 다음월 탐색 → 2/1 (#1, #4 검증)
  - dayMoveFixed=true + dateMoveFixed=true → dateMoveFixed 우선 (#7 검증)
  - dayMoveFixed=true + calendarValueType=year → 동작 안함 (#5 검증)
  - dayMoveFixed=true + calendarValueType=yearMonth → 동작 안함 (#6 검증)
  - 탐색 후 onchange/onviewchange 발생 여부 출력 (#10, #11 검증)

### 분리 여부
- _1 만 — 모든 validation 이 단일 샘플의 con_ 조합으로 충분히 검증 가능

## calendar_P_tabIndex_1.xml

API: `WebSquare.uiplugin.calendar.tabIndex`
설명: Tab 키를 사용하여 컴포넌트 간 포커스를 이동할 때 Calendar 컴포넌트의 순서를 설정합니다.
기본값: Undefined (빈 문자열)

| API 가이드 항목 | 샘플 validation | 케이스 / 검증 방법 | 상태 |
|---------------|---------------|----------------|------|
| @description: Tab 키 포커스 이동 순서를 설정 | description 영역에 반영 | - | OK |
| @propval Undefined (default): Tab 키 기본 포커스 이동 순서에 포함 | (1) "미설정(Undefined) 시 Tab 키에 의한 기본 포커스 이동 순서에 포함됩니다." | con_tabIndex='' (미설정) + focusOnOuterDiv=true → 최외곽 div tabindex='0' 자동 부여 / focusOnOuterDiv=false → 미적용 | OK |
| @propval 0: Tab 키 기본 포커스 이동 순서에 포함시킴 | (2) "'0' 설정 시 Tab 키에 의한 기본 포커스 이동 순서에 포함시킵니다." | con_tabIndex='0' → 최외곽 div tabindex='0' 적용 | OK |
| @propval Pos Int: Tab 키 포커스 이동 순서를 양의 정수로 설정 | (3) "양의 정수(Pos Int) 설정 시 Tab 키에 의한 포커스 이동 순서를 양의 정수로 설정합니다." | con_tabIndex='5' → 최외곽 div tabindex='5' 적용 | OK |
| @propval Neg Int: Tab 키 포커스 이동에서 제외 | (4) "음의 정수(Neg Int) 설정 시 Tab 키에 의한 포커스 이동에서 제외합니다." | con_tabIndex='-1' → 최외곽 div tabindex='-1' 적용 → Tab 순회에서 제외 | OK |
| @spec: 양수로 설정된 컴포넌트 중 작은 숫자부터 포커스 받음 / 같은값은 소스 정의 순서 | (5) "양수로 설정된 컴포넌트 중 작은 숫자의 컴포넌트부터 포커스를 받습니다. 같은값인 경우 소스에 정의된 순서대로 포커스가 이동합니다." | btn_getInfo 의 [Tab 키 포커스 이동 순서 규칙] 출력 | OK |
| @spec: 양수 순회 후 0 또는 미설정 컴포넌트로 이동 (소스 정의 순서) | (6) "양수로 설정된 컴포넌트를 모두 순회한 후 0 또는 미설정 컴포넌트로 포커스가 이동합니다. 0 또는 미설정 컴포넌트는 소스에 정의된 순서대로 포커스가 이동합니다." | btn_getInfo 의 [Tab 키 포커스 이동 순서 규칙] 출력 | OK |
| @spec: tabIndex 가 빈 문자열이 아니면 해당 값이 최외곽 div 에 적용 | (7) "tabIndex 속성이 빈 문자열이 아니면 해당 값이 최외곽 div 에 적용됩니다." | con_tabIndex='0'/'5'/'-1' → render.getAttribute('tabindex') 가 설정값과 동일 | OK |
| @spec: tabIndex 가 빈 문자열 + focusOnOuterDiv=true 이면 tabIndex='0' 자동 부여 | (8) "tabIndex 속성이 빈 문자열이고 focusOnOuterDiv=true 이면 tabIndex='0' 이 자동으로 부여됩니다." | con_tabIndex='' + focusOnOuterDiv=true → render.getAttribute('tabindex')='0' (engine line 1680) | OK |
| @spec: tabIndex 가 빈 문자열 + focusOnOuterDiv=false 이면 최외곽 div 에 tabIndex 미적용 | (9) "tabIndex 속성이 빈 문자열이고 focusOnOuterDiv=false 이면 최외곽 div 에 tabIndex 가 적용되지 않습니다." | con_tabIndex='' + focusOnOuterDiv=false → render.getAttribute('tabindex')=null | OK |
| @spec: accessibility=true 이면 focusOnOuterDiv=true 강제 → 간접적으로 tabIndex='0' 적용 | (10) "accessibility=true 이면 focusOnOuterDiv 속성이 true 로 강제 전환되어 간접적으로 tabIndex='0' 이 적용됩니다." | con_tabIndex='' + accessibility=true → focusOnOuterDiv 자동 true 전환 → tabindex='0' (engine line 1079-1084) | OK |
| @spec: 컴포넌트가 포커스를 받을 수 없는 상태이면 tabIndex 값과 무관하게 포커스 이동 없음 | (11) "컴포넌트가 포커스를 받을 수 없는 상태이면 tabIndex 속성값에 관계없이 포커스가 이동하지 않습니다." | btn_getInfo 의 [포커스 수신 가능 여부] 출력 + 결정 규칙 평가 | OK |
| @related: accessibility, focusOnOuterDiv, focus | con_focusOnOuterDiv / con_accessibility 옵션 제공, onfocus 이벤트 핸들러로 검증 | - | OK |

### 케이스 구성 (con_ 옵션 조합)
- 동적 con_ 조합:
  - con_tabIndex: '' (미설정) / '0' / '5' / '-1'
  - con_focusOnOuterDiv: true / false
  - con_accessibility: true / false
- 검증 시나리오 (결정 규칙 평가 로직 기반):
  - con_tabIndex='5' → 최외곽 div tabindex='5' (#3, #7 검증)
  - con_tabIndex='0' → 최외곽 div tabindex='0' (#2, #7 검증)
  - con_tabIndex='-1' → 최외곽 div tabindex='-1' (#4, #7 검증)
  - con_tabIndex='' + focusOnOuterDiv=true → tabindex='0' 자동 (#1, #8 검증)
  - con_tabIndex='' + focusOnOuterDiv=false → tabindex 미적용 (#1, #9 검증)
  - con_tabIndex='' + accessibility=true → tabindex='0' 강제 (#10 검증)
  - btn_getInfo 의 [Tab 키 포커스 이동 순서 규칙] / [포커스 수신 가능 여부] 출력 (#5, #6, #11 검증)
