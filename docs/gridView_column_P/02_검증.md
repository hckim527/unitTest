# gridView.column P 샘플 — 검증 결과

### gridView_column_P_disabled_1.xml / _2.xml / _3.xml (column.disabled)

- **분할 구성** : 형제 속성 `gridView_column_P_readOnly_1~4.xml` 의 분할 기준(값 고정 → 샘플 분리, con 셀렉트박스 없음)을 그대로 따름.
  - `_1` : col2 에 `disabled="true"` 생성 시 고정 (`disabledClass="tc_disabled_target"`), col3 은 `readOnly="true"` 대조 Column, col1·col4 편집 대조 → @propval true / @spec1 / @spec2 / @spec3
  - `_2` : col2 `disabled="false"` 명시, col3 `disabled` 속성 미설정 → @propval false(default) 2분할
  - `_3` : 정적 2그리드(target1=disabled 메소드 / target2=readOnly 메소드 + `readOnlyPriority="row"`) → @description| 단위별 관리 / @spec4
- **구조** : `onpageload` async + `await comp_init()`, `$c.gcm.getTestGroup()`, `createDynamicDataList` + `setJSON` 자연값 4행, gBody Column `editType="text"`, `focusMode="cell"`, `createEList(["oncellclick","oncelldblclick","onkeydown"])`, 확인 버튼 진입 시 `bottom.btn_clear_onclick()` — 모두 형제 readOnly 샘플과 동일 패턴.
- **MCP 런타임 실측 (playwright2, port 62734) : 세 샘플 모두 console error 0 / warning 0.**

**운영 메모**

- `comp_init` 에서 `target1` 만 remove 하면 동일 cID 의 `label1` 이 잔존해 `dynamicCreate` 가 undefined 를 반환 → `label1.remove()` 추가(Target 재생성 후 라벨 DOM 1개 유지 확인).
- `_1`/`_2` 확인 버튼의 편집 진입 프로브는 **마지막 프로브를 편집 불가 Column 으로 배치**해 편집모드 잔존 상태로 재생성될 때 발생하는 엔진 콘솔 에러를 회피(상세는 03_보강.md).
- **경로/파일명 사고 복구** : 작업 중 `sample/gridView_column/` 의 XML 전체가 `gridView_` 접두어가 제거된 `column_P_*.xml` 로 일괄 리네임되어 `_wpack_` 산출물명까지 어긋나 페이지 로딩 실패(alert) 발생. 지정된 명명 규칙(`gridView_column_P_<name>_<n>.xml`) 으로 복원 후 전량 재변환하여 정상화(readOnly_1·readOnly_4·copyOption_1 로딩 확인). `column_P_disabledClass_1.xml` 은 타 에이전트 소유라 손대지 않음.
