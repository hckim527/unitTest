**@spec4 의 실제 규칙 차이 (실측)**

동일한 단위·동일한 값을 disabled 메소드(`setDisabled("grid")` / `setRowDisabled` / `setColumnDisabled` / `setCellDisabled`)와 readOnly 메소드(`setGridReadOnly` / `setRowReadOnly` / `setColumnReadOnly` / `setCellReadOnly`)로 각각 설정해 대비:

- **disabled** : 적용 순서가 `GridView < [Row|Column] < Cell` 로 **고정**이며 Row/Column 은 항상 **결합조건(OR)** — 둘 중 하나만 true 여도 교차 Cell 은 비활성화.
- **readOnly** : 적용 순서가 `readOnlyPriority` 속성값에 따라 달라짐(`""`=OR / `row`=Row 우선 / `column`=Column 우선). disabled 에는 이에 대응하는 우선순위 속성이 없음.
- 판별 셀 `Cell(2,col2)` (Row=false, Column=true) : **disabled 실효 true(더블클릭 시 이벤트도 편집도 없음) vs readOnly(priority=row) 실효 false(편집 진입 성공, isEditing=true)**.
- 대조 셀 `Cell(1,col3)` (Row=true, Column=false) : 양쪽 모두 true(편집 불가) — 값 조합에 따라 결과가 갈리는 것이지 항상 다른 것은 아님.

**결함/불일치**

- **@spec2 부분 불일치 (결함 의심)** — Column 단위 disabled 인 Cell 에서 **마우스 이벤트는 정상 차단되나 키보드 이벤트는 차단되지 않는다.**
  - 실측(`_1`, `focusMode="cell"`) : disabled Column(col2) 셀 클릭 → `oncellclick` 미발생(정상), 더블클릭 → `oncelldblclick` 미발생·편집 오버레이 없음(정상). 그러나 클릭으로 DOM 포커스가 해당 셀(`mf_target1_cell_0_1`)로 이동하고, 이어서 키를 누르면 **`onkeydown` 이 발생**(keyCode 전달됨).
  - 대조 1 : GridView 전체를 `setDisabled("grid", true)` 로 비활성화하면 클릭·키 입력 모두 이벤트 미발생(정상).
  - 대조 2 : 그리드 밖에 포커스가 있는 상태의 키 입력은 `onkeydown` 미발생 → 위 발생이 셀 포커스 이동에 기인함이 확인됨.
  - 가이드 `column.disabled @spec2` 및 `setColumnDisabled @spec`("disabled 상태는 입력/포커스/이벤트 전체를 차단합니다") 와 어긋남. Jira 확인 대상.
- **참고(정상)** — `getColumnDisabled` 는 미설정 Column 과 `false` 설정 Column 모두 `false` 를 반환(`setColumnDisabled @spec` 의 "미설정 상태와 false 설정 상태를 구분할 수 없습니다" 와 일치). `_2` 의 두 validation 은 실효 상태·편집 가능 여부로 구분해 검증.
- **(엔진 일반 결함, 본 샘플 고유 아님) 편집모드 상태에서 gridView 제거 시 콘솔 에러** — Body Cell 이 편집모드인 채로 gridView 를 `remove()` 하면 `TypeError: Cannot read properties of undefined (reading 'viewChangeAfterEdit')` 가 제거된 컴포넌트(`[mf_target1] [removed]`) 의 `_afterEndEdit` 에서 발생. 기존 샘플 `sample/gridView/gridView_M_setDisabled_1.xml` 에서도 셀 더블클릭(편집 진입) 후 `Target 재생성` 만으로 동일 재현. 본 샘플은 확인 버튼의 마지막 편집 프로브를 편집 불가 Column 에 배치해 회피.
