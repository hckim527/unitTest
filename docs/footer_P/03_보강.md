#### 구성 방식 (정적 배치 확정 근거)

- 배포 엔진(R1641)에 `footer` uiplugin 미탑재. 엔진 번들 내 해당 문자열은 `WebSquare.uiplugin.group.html5={article:"div",aside:"div",footer:"div",...}` 뿐이며, 이는 `group.toHTML()` 의 **IE6/7/8 전용 tagname 폴백표**로 지원 근거가 아님. `controlFactory.createControlHash` 에도 미등록.
  - ※ `_websquare_/uiplugin/` 폴더 목록은 지연 로딩 플러그인만 담으므로(span/button/input 도 없음) 미탑재 판단 근거가 되지 않는다.
- `$p.dynamicCreate` 사용 불가 (동일 계열 `article`/`aside`/`section`/`nav` 로 실측 확정, `footer` 동일):
  - `dynamicCreate(id,"footer",'<footer…>',parent)` → `Cannot read properties of undefined (reading 'then') at d.createControl`. XML 문자열을 주면 2번째 인자 pluginName 은 무시되고 노드 localName 으로 플러그인이 결정됨.
  - config `/WebSquare/dynamicCreate/parseChild/@value="true"` 강제 → `t.appendTo is not a function` 로 여전히 실패.
  - `dynamicCreate(id,"group",'<xf:group tagname="footer">')` → 렌더는 되나 `class="w2group "` 기본 클래스가 붙어 본 API 의 `@spec`(기본 클래스 미추가)과 정면 배치 → 부적합.
- 정적 `<footer>` 는 raw HTML pass-through 로 렌더되어 class/id 가 가이드와 일치 → DOM(`document.querySelector`) 기준 검증 유효 (MCP 실측으로 확인).
- 따라서 UT_01 §7 정적 컴포넌트 배치 규칙 적용 (`wf_body_sample` 삭제, `grp_sample > grp_comp` 직접 배치, `comp_init`/`Target 재생성` 버튼 없음).
- `cm/gcc/common.xml`, `websquare/config.xml` 무수정. class 검증용 CSS 는 공용 `css/tc.css:45-46` 의 `.oddClass`(border 1px solid red) / `.evenClass`(border-radius 15px) 재사용(샘플 자체 style 블럭 없음).

### 구성 방식 (정적 배치 확정 근거)

- 배포 엔진(R1641)에 `footer` uiplugin 미탑재. 번들 내 해당 문자열은 `WebSquare.uiplugin.group.html5={article:"div",aside:"div",footer:"div",...}` 뿐이며 이는 `group.toHTML()` 의 **IE6/7/8 전용 tagname 폴백표**로 지원 근거가 아님. `controlFactory.createControlHash` 에도 미등록.

### 특이사항 (엔진 제약 / 가이드 대비)

- `@spec` 3(예약어 id 오류)은 원문이 "오류가 발생할 **수 있습니다**"(가능성)이며, 실측상 `id="style"` 로 선언해도 **JS 오류 0건, id 가 `style` 그대로 렌더**된다. `footer` 는 uiplugin 이 아닌 raw HTML pass-through 라 엔진의 예약어 충돌 경로 자체를 타지 않기 때문 — `article`/`aside`/`section`/`nav` 계열과 동일. 결함이 아니라 "가능성" 문구의 미해당 케이스로 판단하여 원문 표현을 유지하고 실측값(오류 0건)을 그대로 출력한다.
- id 미설정 시 자동 부여 형식은 `wq_uuid_NN` (WebSquare 컴포넌트의 `mf_wq_uuid_NN` 과 달리 `mf_` 없음). 번호는 엔진 전역 카운터라 고정값 아님 → TSQA 기대값은 패턴 매칭 필요.
