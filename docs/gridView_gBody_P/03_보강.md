**구성 방식**

- class 검증용 CSS 는 프로젝트 공용 `css/tc.css` 의 `.oddClass` / `.evenClass` 사용.
- footer 판(`footer_P_class_1.xml`)과 동일 구조를 유지하되, footer 선언을 제거하고 `w2:gBody` 에만 class 를 설정.

**실측 raw 값 (MCP playwright2, console error 0)**

- 선언 마크업 : `<w2:gBody style="" id="gBody1" class="oddClass evenClass"> ... </w2:gBody>`
- 렌더된 Body 영역 요소 outerHTML(앞부분) :
  `<table id="mf_target1_body_table" class="gridHeaderTableDefault" style="position: absolute; left: 0px; top: 0px; table-layout: fixed; border-collapse: collapse; border-spacing: 0px; width: 554px;">`
- `mf_target1_body_table.className` = **`gridHeaderTableDefault`** (설정한 `oddClass evenClass` **미적용**)
- Body Column 영역 요소 : `td#mf_target1_cell_0_0`, `className` = `w2grid_input_table gridBodyDefault gridBodyDefault_data mf_target1_columnstyle_0_`
- `con_class` = `oddClass`(단일) / `(미설정)` 으로 재생성해도 동일하게 `gridHeaderTableDefault`
- `target1.struct.body.attr` = `{"id":"gBody1","className":"oddClass evenClass"}`

→ **가이드(`@propval |`) 와 실측 일치.** 설정한 class 는 렌더 결과에 반영되지 않고 엔진 기본 클래스만 적용됨. footer 판과 동일한 결론. (article/audio/video/canvas 의 `class` 와 정반대)

**원인 (엔진 소스 대조, 참고)**

- `uiplugin/gridView/layoutController.js:290` : `this.options.bodyTableClass = this.struct.body.attr["class"] || "gridBodyTableDefault";`
- 파서가 `class` 를 **`className` 키로 정규화**해 저장하므로 `attr["class"]` 는 항상 `undefined` → 기본값 폴백. (footer `:301` 과 동일 구조)
- 추가 발견 : `bodyTableClass` 는 290행에서 계산만 되고 **엔진 어디에서도 사용되지 않는다**(gridView 디렉터리 전역 grep 결과 1건). Body 영역 table 은 `:720` 에서 `headerTableClass` 를 재사용해 렌더한다.
  `str += "<table id='" + this.id + "_body_table' class='" + this.options.headerTableClass + ...`
  → 그래서 실측 className 이 `gridBodyTableDefault` 가 아니라 **`gridHeaderTableDefault`** 로 나온다.
- 어느 경로든 "선언한 class 미적용 + 엔진 기본 클래스만 적용" 이라는 가이드 규정과 결과가 일치하므로 **결함이 아니라 현행 스펙**으로 판단.

**@spec 근거 (Body 영역 / Body Column 영역 분리)**

- Body 영역 = `table#mf_target1_body_table` (gBody 의 `class` 대상, 기본 클래스 `gridHeaderTableDefault`)
- Body Column 영역 = `td#mf_target1_cell_0_0` (gBody 의 `columnClass` 대상, 기본 클래스 `gridBodyDefault` 계열)
- 두 영역이 별개 요소·별개 기본 클래스로 렌더됨을 출력해 "별도 정의"를 입증. columnClass 속성 자체의 동작은 검증하지 않음.

**MEMORY 승격**

- `@propval` 이 enum 이 아닌 `<String>` 단일 타입이라 값별 분리 대상이 아니며, default 값 표기가 없어 "미설정 시" 분리 항목도 만들지 않았다. 대신 con_width 에 `(빈값)` / `300px` / `1200px` 3 옵션을 두어 미설정 케이스까지 실행 가능하게 구성.
- `@dynamic N` 이므로 옵션 변경은 `body_sample.xml` 기본 `Target 재생성` 버튼으로만 반영(중복 버튼 미생성).
