### 발견 이슈
1. **공백 2개 설정 시 접두사 체계 붕괴** (gBody/header 판과 동일 동작)
   - `layoutController.js:846` `cell["class"] = className + " " + className + "_data";` 로 문자열 전체를 두 번 붙이고 마지막 토큰에만 접미사를 붙임.
   - 결과 `tcSubClass tcEtcClass tcSubClass tcEtcClass_data` → 첫 토큰 중복, `_rowNumber`/`_rowStatus` CSS 미적용.
2. **subtotalClass 를 일부 SubTotal 에만 설정하면 나머지 SubTotal 의 RowNum/RowStatus Cell 클래스가 리터럴 `undefined`**
   - `drawInitializer.js:753` 이 `subtotalStrList[targetID].attr.subtotalClass` 를 fallback 없이 tdClass 로 넘김
     (`getTableHtml(..., this.subtotalStrList[targetID].attr.subtotalClass)`).
   - 반면 데이터 Cell 경로(`layoutController.js:1141` `struct.attr.subtotalClass || "gridSubtotalDefault"`)에는 fallback 이 있어 `gridSubtotalDefault` 로 정상 처리됨 → 같은 Row 안에서 비대칭.
   - 증상 : `undefined undefined_rowNumber`, `undefined undefined_rowStatus` (배경 transparent).
   - 가이드에는 이 동작이 없음. validation 문구는 유지하고 실측값만 결과창에 노출.

### 구성
- Body Column : `name` / `dept` / `team` / `amount` (4개), 데이터 6행
- SubTotal Row 의 마지막 Cell 은 `inputType="expression"` (`sum('amount')`) → 소계값으로 그룹 범위를 실측
- 옵션 (모두 dynamic N → `Target 재생성` 으로만 반영, 별도 재생성 버튼 없음)
  - `con_targetColumnID` : (미설정) / `dept` / `team` / `noSuchCol` / `dept team`
  - `con_dataSet` : `sorted`(dept 정렬 + team 이 dept 안에서만 연속) / `crossed`(dept 정렬 + team 이 dept 경계를 넘어 연속) / `scattered`(dept 값 흩어짐)
  - `con_subTotalDefine` : `1`(SubTotal 1개) / `2`(1번째=targetColumnID, 2번째=team) / `2r`(1번째=team, 2번째=targetColumnID)
- 검증 버튼 : `SubTotal Row 확인` — Body Table `tbody > tr` 을 렌더 순서대로 훑어 데이터 Row / SubTotal Row 와 각 Cell 값을 실측 출력

### SubTotal Row 의 DOM 렌더 형태 (실측)
- Body Table `table#{gridId}_body_table` 은 **thead(헤더 tr) + tbody** 구조 → 행 수집 시 반드시 `tbody > tr` 로 한정할 것
- 데이터 Row : `tr[data-tr-id="brow1"].grid_body_row` (남는 filler 행은 `.w2grid_hidedRow` + `display:none`)
- SubTotal Row : `tr[data-subtotal="{targetColumnID}_{subTotal 내 row 순번}"]`
  - `data-targetcolumnid="{targetColumnID}"` 동시 부여 (targetColumnID 미설정이면 두 속성 모두 문자열 `undefined` 기준)
  - `id` 는 선언한 `<w2:row>` 의 id 가 그대로 유지되나 클론마다 중복되므로 고유 식별자로 쓸 수 없음
  - **표시되는 SubTotal Row 에만 `data-subtotalrowindex="{직전 데이터 rowIndex}"`** 가 설정됨. 숨김 클론은 `style="display:none"` 이고 이 속성이 없음
- 데이터 Row 1개마다 SubTotal 정의 수만큼 SubTotal 클론 tr 이 미리 깔려 있고, 경계에서만 `display` 를 풀어 노출

### 발견 이슈
1. **공백 2개 설정 시 접두사 체계 붕괴** (columnClass/gBody/header 판과 동일 동작, 근거 `layoutController.js:846`)
   - 가이드는 "설정할 수 없습니다" 라는 제약만 서술하고 실동작을 규정하지 않음 → validation 문구 유지, 실측만 노출.
2. **subtotalClass 를 일부 SubTotal 에만 설정하면 나머지 SubTotal 의 RowNum/RowStatus Cell 클래스가 리터럴 `undefined`** (케이스 B)
   - `drawInitializer.js:753` : `getTableHtml(this.subtotalStrList[targetID], "tbody", "td", this.subtotalStrList[targetID].attr.subtotalClass)` — fallback 없이 undefined 전달.
   - `layoutController.js:1391/1408` 에서 `tdClass + " " + tdClass + "_rowNumber"` 로 조립 → `undefined undefined_rowNumber`.
   - 데이터 Cell 경로(`layoutController.js:1141` `struct.attr.subtotalClass || "gridSubtotalDefault"`)에는 fallback 이 있어 `gridSubtotalDefault` 로 정상 → **같은 Row 안에서 비대칭**.
   - 가이드 `@spec2` 는 `{subtotalClass} {subtotalClass}_rowNumber` / `_rowStatus` 를 규정하고 `@propval` 은 미설정 시 `gridSubtotalDefault` 를 규정하므로, 이 조합은 `gridSubtotalDefault gridSubtotalDefault_rowNumber` 여야 함 → **가이드 불일치**.
   - 단, subtotalClass 를 모든 SubTotal 에 설정하거나(A) 아무데도 설정하지 않으면(C) 정상.

### 구성

| 300px | 80 | 639px | 139 + 140 + 140 + 140 | 639px |

- 컴포넌트 조회 : `getComponentById("subTotal1")` → `undefined (조회 결과 없음)` / 렌더된 SubTotal Row id(`srow1`) → `같은 id 의 TR DOM 엘리먼트 19 개 목록 (컴포넌트 객체 아님)` (예비 클론 Row 포함, `window[id]` fallback 이 HTMLCollection 반환) / width 조회·변경 대상 컴포넌트 객체 존재 여부 = `false`

### 수정 이력
1. SubTotal Column 폭 일치 판정을 `=== 선언값` → `차이 <= 2px` 로 완화 (테이블 테두리로 첫 Cell 만 139px 렌더되어 140 설정 시 오판정)
2. `lookupComponent` 에 HTMLCollection/NodeList 분기 추가 (기존에는 `[object HTMLCollection]` 로만 출력되어 의미 불명)

### 발견 이슈
1. **`@propval` 하위절과 실측 불일치** — 가이드는 "SubTotal 영역의 너비는 SubTotal Column 으로 결정됩니다" 라고 규정하나, SubTotal Column width 를 80/140/200 으로 바꿔도 렌더 폭은 항상 `139 + 140 + 140 + 140` 으로 **Header Column width(140) 를 따른다.**
   - 근거 : `layoutController.js` `initializeTableInfo()` 가 head -> body -> foot 순으로 `_getColInfo()` 를 호출하고 `colWidthList[x] == null` 일 때만 기록(선착순) -> Header 선언값이 항상 선점.
   - validation 문구는 가이드 원문 유지, 실측값을 결과창 `[컬럼]` / `[대비]` 줄에 노출.
2. subTotal 태그 자체의 `width` 는 300px/1200px 어느 값이든 렌더에 무반영이며 DOM 에 흔적도 남지 않음 → `@propval` 의 "참고용" 서술은 실측과 일치.
