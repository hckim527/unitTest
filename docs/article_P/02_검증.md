### 구성 방식 (참조 샘플과 다른 점 / 사유)

- 참조 샘플(`span/group/*_P_class_1.xml`)은 `common_P/common_P_class_1.xml` 을 wframe 으로 감싸는 wrap 패턴이며 `$c.gcm.createBasicXxx` + `$p.dynamicCreate` 로 target 을 동적 생성한다.
- **article 은 현재 배포 엔진에 uiplugin 이 등록되어 있지 않다.** (아래 "엔진 제약" 참조) → `$p.dynamicCreate(id, "article", ...)` 실패, 컴포넌트 객체(`target1.getStyle` 등) 미생성.
- 따라서 `UT_01_생성.md` §7 "정적 컴포넌트 배치 규칙" 을 적용하여 `wf_body_sample` 대신 `grp_sample > grp_comp` 를 직접 배치하고 `<article>` 을 정적으로 두었다. (Target 재생성 버튼 / `comp_init` 불필요)
- `class` 는 `@dynamic N` (렌더 시점 전용) 이므로 con_ 셀렉트박스 + 재생성 방식이 아니어도 검증에 지장 없음. class 설정본(target1) / 미설정본(target2) 2개를 정적 배치해 대비 검증.
- `cm/gcc/common.xml` 에 `createBasicArticle` 은 **추가하지 않았다** (동적 생성 불가로 사용처 없음). 공용 파일 무수정.

### 엔진 제약 (결함 아님 / 미구현)

- 라이브 엔진: `websquare_26.0813` Studio 가 서빙하는 **R1641**(`websquare-ai_6.0_0.1641R.20260812`).
- 이 엔진에는 `article` uiplugin 이 없다. `_websquare_` 번들에는 group 플러그인의 legacy html5 매핑(`html5={article:"div", ...}`) 만 존재.
- `<article>` 태그는 컴포넌트가 아니라 **raw HTML 마크업으로 통과(pass-through)** 되어 렌더된다. 결과적으로 class/id 동작은 API 가이드 `@spec` 과 일치하지만, 컴포넌트 객체·메소드는 존재하지 않는다.
- API 가이드 원본(`C:\ai_engine_bak\websquare\uiplugin\article\article.js`) 은 `@tagversion 2.0` 신규 컴포넌트로, 배포 엔진 반영 전 상태로 보인다.
