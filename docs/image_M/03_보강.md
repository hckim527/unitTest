### 필수 파라미터(Y) 빈값/미전달 처리 판단

- `@param <String:Y:->` 는 필수(Y)이므로 UT_01_생성.md §2 의 "필수여부 N 인 param 생략 시 기본값 동작 validation/생략 로직" 대상이 아니다 → 미전달 케이스·validation 을 만들지 않음.
- 빈 문자열 전달 시의 동작은 API 가이드(@param/@spec/@return) 어디에도 정의가 없어, 임의 validation 추가 금지 규칙에 따라 항목화하지 않음. par_alt 셀렉트박스도 빈값 옵션 없이 텍스트 2종만 제공.
- 다만 "alt 가 없는 상태 → setAlt 로 설정" 대비는 **초기 생성 시 alt 미선언**으로 확보한다(호출 전 = alt 속성 미출력 / 16x16).

### 짝 샘플 image_P_alt_1.xml 과의 관점 차이

- P 샘플: `alt` 를 **선언 시점**(con_alt → dynamicCreate)에 주고 렌더 결과를 관측.
- M 샘플: target 을 **alt 없이 생성**한 뒤 **동적 호출 시점**(btn_setAlt)에 setAlt 로 주입하고, 같은 판정 수단(표시 상태·접근성 이름·마크업 alt)의 **호출 전 → 호출 후 변화**를 한 줄에 대비 출력.
- 그래서 con_ 은 alt 를 제외한 전제(src / ariaLabel)만 제공하고, alt 는 par_ 파라미터로만 들어온다.
- 엔진 소스 차이: 선언 경로는 alt 가 빈값이면 속성 자체를 마크업에 넣지 않지만, `setAlt` 는 `this.render.alt = alt` 로 DOM 속성을 직접 설정한다(`image.js` L1314).

## image_M_setLongdesc_1.xml

API: `WebSquare.uiplugin.image.setLongdesc`
설명: Image 컴포넌트의 longdesc 속성을 설정합니다.

| API 가이드 항목 | 샘플 validation | 케이스 | 상태 |
|---------------|---------------|------|------|
| @description: Image 컴포넌트의 longdesc 속성을 설정합니다. | description 영역에 반영 | - | OK |
| @param `<String:Y:->` Url: Image 컴포넌트에 로드된 이미지의 상세 설명 페이지를 URL 로 설정합니다. | (1) "Url(필수) 파라미터로 Image 컴포넌트에 로드된 이미지의 상세 설명 페이지를 URL 로 설정합니다." | par_Url 선택 → btn_setLongdesc → [1] 마크업 longdesc / getLongdesc() 를 호출 전 대비로 출력 | OK |
| @spec: HTML5 미지원 속성으로 alt, ariaLabel, title 등의 속성 사용을 권장합니다. | (2) 동일 문구 | [2] 접근성 이름 소스(alt/ariaLabel/title 만) + 상세 설명 UI 노드 0개 + 렌더 영역 무변화 | OK |
| @related: image.longdesc / image.getLongdesc | (제외) | @related 는 별개 API 이므로 항목화하지 않음. getLongdesc() 는 set 결과 확인 수단으로만 사용 (UT_01 §5) | 제외 |

### @spec 처리 판단 (짝 샘플 삭제 선례 반영)

- 짝 샘플 `image_P_longdesc_1.xml` 에서는 @spec 이 "alt, ariaLabel, title 등의 속성 사용을 권장합니다." **단독 문장**이었고, 대비용 con_alt/con_ariaLabel/con_title 제거로 검증 수단이 사라져 사용자 결정으로 삭제되었다. 반면 @description 하위절 "하위 버전 호환을 위한 속성이며 HTML5 에서 지원하지 않습니다." 는 유지되어 [3] 으로 검증 중이다.
- setLongdesc 의 @spec 은 그 둘이 **한 문장**("HTML5 미지원 속성으로 alt, ariaLabel, title 등의 속성 사용을 권장합니다.")으로 합쳐진 형태다. M 가이드에는 @description 하위절이 없어, 이 문장을 통째로 빼면 P 샘플에서 검증 가능하다고 확정된 "HTML5 미지원" 사실이 M 샘플에서 완전히 사라진다.
- 따라서 **문장을 쪼개거나 삭제하지 않고 원문 그대로 1항목**으로 유지하고, P 샘플 [3] 과 동일 계열의 수단(접근성 이름 소스 / 상세 설명 UI 노드 수 / 렌더 영역 무변화)으로 검증한다.
- P 에서 삭제 사유였던 "검증 수단 부재"는, alt/ariaLabel/title 을 조작하는 con_ 을 새로 만들지 않고 **접근성 이름 소스 목록**을 출력하는 방식으로 해소했다 — 다른 API(alt/ariaLabel/title)의 동작을 검증하지 않으므로 UT_01 §2 "타 기능 유효성 제외" 와도 충돌하지 않는다.

### 필수 파라미터(Y) 빈값/미전달 처리 판단

- `@param <String:Y:->` 는 필수(Y) 이므로 UT_01 §2 의 "필수여부 N 인 param 생략 시 기본값 동작 validation/생략 로직" 대상이 아니다 → 미전달 케이스를 만들지 않음 (setAlt 와 동일 판단).
- 빈 문자열 전달 시 동작은 가이드 어디에도 정의가 없어 임의 추가 금지 규칙에 따라 항목화하지 않음. par_Url 은 URL 2종만 제공.
- "longdesc 없음 → setLongdesc 로 설정" 대비는 **초기 생성 시 longdesc 미선언**으로 확보한다 (호출 전 = 속성 미출력 / getLongdesc() = "").

### 짝 샘플 image_P_longdesc_1.xml 과의 관점 차이

- P 샘플: `longdesc` 를 **선언 시점**(con_longdesc → dynamicCreate → toHTML 이 `longdesc='...'` 마크업 문자열 생성, image.js L1010)에 주고 결과 관측.
- M 샘플: target 을 **longdesc 없이 생성**한 뒤 **동적 호출 시점**(btn_setLongdesc)에 주입하고, 같은 판정 수단을 **호출 전 → 후 대비**로 출력. grp_condition(con_) 자체가 없고 값은 par_Url 로만 유입된다.
- 엔진 경로 차이: 선언 경로는 마크업 속성 문자열, `setLongdesc` 는 `this.render.longDesc = longdesc` 로 **IDL 프로퍼티**를 설정한다 (image.js L1253~1255).

### IDL(`render.longDesc`) 설정의 실제 반영 — MCP 실측

- `setLongdesc("/sample/image/image_longdesc.html")` 호출 후 `img.getAttribute("longdesc")` = `"/sample/image/image_longdesc.html"`, 직렬화 마크업 = `<img id="mf_target1" src="/img/png.png" class="w2image " longdesc="/sample/image/image_longdesc.html">`
  → longDesc 는 content attribute 를 반영(reflect)하는 IDL 이므로 **선언 경로와 최종 마크업 결과가 동일**하다. 경로만 다르고 결과 차이는 없음.
- `getLongdesc()` 반환값 = `"http://127.0.0.1:60188/sample/image/image_longdesc.html"` — **설정값이 아니라 절대 URL 로 정규화**되어 돌아온다 (`longDesc` 가 URL-reflecting IDL 이기 때문). 가이드 @return "longdesc 속성값을 반환합니다" 와 문자열이 일치하지 않으므로 샘플은 실측값을 그대로 출력한다.
- 미설정 상태의 `getLongdesc()` = `""` — 가이드 @return "값이 없는 경우 ''(Empty String) 반환" 과 일치.
- CDP Accessibility.getFullAXTree 실측: 대상 img 의 name sources = `aria-labelledby, aria-label, alt, title` 4종뿐이고 **longdesc 는 등장하지 않음** → HTML5 미지원(브라우저 동작 미반영) 판정 근거. `HTMLImageElement.prototype` 에 `longDesc` IDL 은 여전히 존재하므로 IDL 유무는 근거로 쓰지 않았다.

- par_Url 옵션값은 짝 P 샘플과 동일 문자열을 사용한다. 두 리소스 파일은 실제로 존재하지 않지만 longdesc 는 브라우저가 fetch 하지 않는 속성이라 판정에 영향이 없다(404 요청도 발생하지 않음, console error 0 확인).
- Target 재생성 버튼으로 초기(longdesc 미설정) 상태 복원 후 재호출 정상 동작 확인.

## image_M_getLongdesc_1.xml

| API 가이드 항목 | 샘플 validation | 상태 |
|---|---|---|
| `@description` Image 컴포넌트에 설정된 longdesc 속성값을 반환합니다. | description 필드 (문장 1개) | ✓ |
| `@return <String> result` longdesc 속성값을 반환합니다. | (1) longdesc 속성값을 반환합니다. | ✓ |
| `@return` `|` longdesc 속성값이 없는 경우 ""(Empty String)을 반환합니다. | (2) longdesc 속성값이 없는 경우 ''(Empty String)을 반환합니다. | ✓ |
| `@param` (없음) | - | 해당 없음 (par_ 컨트롤 미생성) |
| `@spec` (비어 있음) | - | 해당 없음 (임의 항목 생성 금지) |
| `@related longdesc` / `@related setLongdesc` | - | 제외 (UT_01 §2 @related 는 검증 대상 아님) |

### 반환값 변화 수단 — con_longdesc 선언 채택 근거

- 후보 ① `con_longdesc`(선언 시점) ② `setLongdesc()` 호출 버튼(동적 변경) 중 **①** 채택.
- UT_01 §2 는 `@related` API 를 호출하는 **검증 버튼/핸들러 생성을 금지**한다. ② 는 `@related` 인 setLongdesc 를 호출하는 버튼이 필요해 이 금지에 직접 저촉된다.
- UT_01 §5 의 get/set 쌍 규칙은 "**set 샘플**에 get 확인 로직을 넣으라"는 단방향 규칙이며, get 샘플에 set 버튼을 요구하지 않는다.
- ① 은 렌더 시점에 결정되는 전제일 뿐 버튼/핸들러를 추가하지 않으며, `@return` 하위절(미설정 → Empty String)을 con 빈값 옵션으로 자연스럽게 확보한다 (UT_01 §4 con_ 은 Target 재생성 버튼으로만 반영).

### 정규화 — 3자 비교 MCP 실측 (127.0.0.1:60188, playwright 세션 1, console error 0)

| con_longdesc (선언 설정값) | 마크업 `getAttribute("longdesc")` | `getLongdesc()` 반환값 |
|---|---|---|
| `/sample/image/image_longdesc.html` | `/sample/image/image_longdesc.html` | `http://127.0.0.1:60188/sample/image/image_longdesc.html` |
| `/sample/image/image_longdesc.txt` | `/sample/image/image_longdesc.txt` | `http://127.0.0.1:60188/sample/image/image_longdesc.txt` |
| (미설정) | `null` (속성 미출력) | `""` |

- **선언 경로에서도 정규화가 동일하게 발생**한다. `getLongdesc()` 는 `this.render.longDesc`(URL-reflecting IDL)를 반환하므로 설정 경로(선언/`setLongdesc`)와 무관하게 **절대 URL** 로 돌아온다. → 가이드 `@return` "longdesc 속성값을 반환합니다" 와 문자열이 불일치. 샘플은 실측값을 가공 없이 출력하고 마크업 속성값을 나란히 찍어 차이를 드러낸다.
- 미설정 시 `getLongdesc()` = `""` (`=== "" → true`, `=== null → false`, `typeof "string"`). 마크업은 `hasAttribute("longdesc") === false`. → `@return` 하위절과 일치.
- 출력은 validation 2항목 = `setReturnValue` 2줄. `''` 는 화면에서 보이지 않으므로 반환값을 항상 작은따옴표로 감싸 `null`/`없음` 과 눈으로 구분되게 했다.

### `@spec`(DataList / DataMap 구분 불가) 검증 방식

**별도 판정 줄을 두지 않고 두 반환값 줄 자체로 판정한다.** DataList 바인딩과 DataMap 바인딩의 출력이 각각

- `ref = data:dlt_image.imgPath -> 반환값 : { id : mf_dlt_image, ref : data:dlt_image.imgPath }`
- `ref = data:dtm_image.imgPath -> 반환값 : { id : mf_dtm_image, ref : data:dtm_image.imgPath }`

로, **양쪽 모두 키가 `id` 와 `ref` 뿐이고 DataCollection 종류를 알려주는 값이 없다는 사실이 값 자체로 드러난다.** 키 목록을 다시 뽑아 `동일 : true` 로 판정하는 줄은 같은 사실의 반복이므로 두지 않는다(UT_01 §4-1). 이 근거는 핸들러 주석에 남겨 두었다.

- 이전 구성(정적 target2 / target3 고정 바인딩 + `imgPath2` 컬럼·키, `gVar` 키 목록 누적 대비)은 사용자 요청으로 **전부 제거**했다.
- 출력에는 **validation 번호 접두사를 쓰지 않으며**, 케이스별 출력은 **1줄, 값만**이다. `typeof` / `null 여부` 같은 파생 정보도 값에서 바로 도출되므로 출력하지 않는다(UT_01 §4-1).
- `scwin.strInfo` 실측 : `null` -> `"null"`, `undefined` -> `"undefined"`, 객체 -> `"{ id : ..., ref : ... }"` 로 **세 값이 서로 다른 문자열**로 출력되어 값만으로 구분된다.

### 가이드 서술과 다른 동작 (결함 후보)

- 가이드 `@return` 하위절은 "ref 속성을 설정하지 않았거나 **잘못된 값이면 null** 을 반환합니다" 인데, 실제로는 **잘못된 값일 때 `undefined` 를 반환**한다.
- 원인: 존재하지 않는 DataCollection ID(`data:invalid.imgPath`) 를 ref 에 주면 `modelControl.isDataCollectionRefBinded` 가 **true** 인데 `dataCollectionRefInfo.dataComp` 는 undefined 다. `image.prototype.getDataListInfo`(image.js:1414) 가 `dataComp.id` 접근에서 TypeError → try/catch 의 `exception.printStackTrace` 로 흡수 → 반환문 없이 종료 → `undefined`.
- 콘솔에 `TypeError: Cannot read properties of undefined (reading 'id') / component : image[mf_target1]` 1건이 함께 남는다.
- 미설정(`ref` 없음) 케이스는 `isDataCollectionRefBinded === false` 로 정상적으로 `null` 을 반환한다.
- 동일 구현(`anchor.js:1622` 등)이 다른 컴포넌트에도 복제되어 있어 공통 결함일 가능성이 있다.
