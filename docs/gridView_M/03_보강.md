#### ⚠️ 실측 사실 (검증 수단 관련)

`delimiter` / `decimalDelimiter` 는 **셀 표시값에 드러나지 않는다.** 표시 구분자는 전적으로 `displayFormat` 마스크가 결정하며(동일 마스크에 delimiter 만 `,`↔`.` 로 바꿔도 출력 동일), 두 파라미터는 원본 모델값 파싱/에디터 측 옵션으로만 반영된다. 따라서 `_2` 는 DOM 표시값 외에 `getCellInfo(colIndex).options.delimiter / .decimalDelimiter` 적용값을 함께 출력하여 검증한다.
부수 사실: 원본 모델값에 천단위 구분자가 들어있으면(예: `1,234,567.89`) 마스크 파싱이 깨져 `NaN` 이 섞인 표시값이 나온다 → 픽스처는 구분자 없는 정수 `1234567` 사용.

**UT_01 §4 규칙 충돌 판단** — §4 는 "rowIndex, colIndex 등의 selectbox 옵션 값은 실제 행/컬럼 개수만큼 설정할 것 (예: 4개 컬럼이면 0,1,2,3)" 으로 규정한다. `99` 옵션은 문언상 이에 어긋난다. 다만 ⓐ UT_01 §2 는 `@return` 을 포함한 가이드 근거를 validation 으로 빠짐없이 반영하도록 요구하고, ⓑ 모든 validation 은 검증 수단(트리거)을 가져야 한다. "유효하지 않은 파라미터 → false" 는 **정의상 유효 범위 밖의 값을 넣어야만** 검증되므로, §4 를 그대로 지키면 해당 validation 이 검증 불가 상태로 남는다. 따라서 **§4 는 "유효한 인덱스를 열거할 때의 범위 규칙"으로 읽고, 유효성 위반 반환값 검증용 값은 그 적용 대상 밖의 불가피한 예외로 보는 것이 타당**하다고 판단한다(`rowIndex 99` 도 동일 근거). 단 §4 원문에 예외 조항이 명시되어 있지 않으므로 **규칙 문서는 임의로 수정하지 않았고**, 명문화 여부는 사용자 판단 영역으로 남긴다.

### gridView_M_setMaxLength_4.xml

**분리 사유**: `@param maxLength` 의 하위 규칙 6종은 전제가 **Body Column 의 `dataType="float"`** 이라 그리드 구성 자체가 text 계열인 _1/_2/_3 과 다르다. 엔진도 `inputType=="text" && (dataType=="float" || bigDecimal float 문자열)` 일 때만 `cellInfo.setFloatMaxLength()` 경로를 타므로 별도 샘플로 분리. 본 항목은 **_4 소유 범위(float 하위 규칙 전체 + @spec3)** 만 다룬다.

**엔진 실존 확인**: `gridViewApiController.prototype.setMaxLength` (gridViewApiController.js:8414) → `useFloatMaxLength = cellInfo.options.dataType == "float" || cellInfo._isBigDecimalFloatMaxLength(maxLength)`, `inputType == "text" && useFloatMaxLength` 이면 `cellInfo.setFloatMaxLength(maxLength)`. `cellInfo.setFloatMaxLength` (cellInfo.js:1430) 은 `this.options.maxlength = this.options.maxLength = "-1"` 로 덮어쓰고 실제 제한은 `_floatMaxLength` 에 보관 → **@spec3 (getMaxLength 가 -1 반환) 의 소스 근거**. 실제 자릿수 제한은 `validator.maxFloatLengthCommand` (validator.js:2081) 가 수행.

| API 가이드 항목 | 샘플 validation | 상태 |
|---|---|---|
| @description 첫문장 | description 필드 | ✓ |
| @param maxLength \| dataType="float" 이면 "." 기준 정수부/소수부 최대 길이 각각 설정 (ex-"5.2") | (1) | ✓ |
| @param maxLength \| "." 기준 정수부에 "*" 설정 또는 생략 시 정수부 제한 없음 (ex-"*.2", ".2") | (2) | ✓ |
| @param maxLength \| "." 기준 소수부에 "*" 또는 "-1" 설정 시 소수부 제한 없음 (ex-"5.*", "5.-1") | (3) | ✓ |
| @param maxLength \| "." 없이 숫자만 설정 시 정수부 최대 길이로 적용되고 소수부 입력 불가 | (4) | ✓ |
| @param maxLength \| "*" 또는 "*." 설정 시 정수부만 제한 없이 입력 가능 | (5) | ✓ |

| @param columnInfo (인덱스 / ID / 숨겨진 Column 포함 / MultiLine 고유 인덱스) | - | 제외(_1/_2/_3 소유) |

| @related getMaxLength / setCellMaxLength / column.* | - | @related 자체는 제외(UT_01 §2). getMaxLength 는 @spec3 검증 및 set 결과 확인 용도로만 호출 |

**구성**: Body Column 1개 `num1` (`inputType="text" editType="text" dataType="float" maxLength="4.1"`, 인덱스 0) + 4행. `par_maxLength` 는 규칙별 예시를 **전수 9종**("5.2", "*.2", ".2", "5.*", "5.-1", "5", "*", "*.", ".") 으로 배치. columnInfo 는 float Column 인덱스 0 고정(인덱스/ID 지정 검증은 _1/_2 소유). 확인 경로 2가지: ⓐ `getMaxLength(0)` 반환값(@spec3) ⓑ 셀 더블클릭 → 편집 오버레이에 긴 숫자 실제 타이핑 → `onafteredit` 에서 입력 결과값의 정수부/소수부 자릿수 출력.

**MCP 실측** (port 57835, console error 0). 각 케이스마다 `setMaxLength(0, 값)` 실행 후 셀(0,0) 편집 오버레이에 `1234567890.123456` 을 **키 단위로 실제 타이핑**한 결과값:

| maxLength | getMaxLength(0) | 타이핑 결과값 | 가이드 기대 | 판정 |
|---|---|---|---|---|
| (초기, XML 속성) | `"4.1"` | - | - | setMaxLength 미실행 시엔 속성 원본 유지 |
| `"5.2"` | `-1` | `12345.12` | 정수5 / 소수2 | ✓ |
| `"*.2"` | `-1` | `1234567890.12` | 정수 무제한 / 소수2 | ✓ |
| `".2"` | `-1` | `1234567890.12` | 정수 무제한 / 소수2 | ✓ |
| `"5.*"` | `-1` | `12345.123456` | 정수5 / 소수 무제한 | ✓ |
| `"5.-1"` | `-1` | `12345.123456` | 정수5 / 소수 무제한 | ✓ |
| `"5"` | `-1` | `12345.` | 정수5 / 소수 입력불가 | ✓ (소수점 뒤 자릿수 0) |
| `"*"` | `-1` | `1234567890.` | 정수만 무제한 | ✓ |
| `"*."` | `-1` | `1234567890.` | 정수만 무제한 | ✓ |
| `"."` | `-1` | `1234567890.` | **전체 입력 제한** | ❌ **불일치** — 입력이 전혀 차단되지 않고 `"*"`/`"*."` 와 동일(정수부 무제한 / 소수부 0) |

핸들러 실동작 확인: `setMaxLength 실행` 버튼 → 리턴창 `setMaxLength(0, '5.2') -> getMaxLength(0) : -1`, 셀 편집 후 포커스아웃 → `입력 결과값 : '98765.98' (정수부 5자리 / 소수부 2자리)`.

**가이드-실측 불일치 (결함 후보)**: `maxLength="."` 만 설정 시 가이드는 "전체 입력이 제한됩니다" 이나 실측은 정수부 무제한/소수부 0. `setCellMaxLength` (2026-07-02 실측) 에서 확인된 것과 **동일 증상이 setMaxLength 에서도 재현**됨. 원인은 공통 경로인 `validator.maxFloatLengthCommand` (validator.js:2084-2090): `integerMax = String(maxLength).split('.')[0] || '*'` 이므로 `"."` 의 정수부 `''` 가 `'*'`(Infinity)로 폴백되고, `fractionMax = split('.')[1] || '0'` 로 소수부만 0 이 된다. → `"*."` 과 구분 불가.
