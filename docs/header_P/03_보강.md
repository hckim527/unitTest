### 구성 방식 (정적 배치 확정 근거)

- 배포 엔진(R1641)에 `header` uiplugin 미탑재. 엔진 번들 내 `header` 문자열은 `WebSquare.uiplugin.group.html5={article:"div",aside:"div",header:"div",...}` 뿐이며, 이는 `group.toHTML()` 의 **IE6/7/8 전용 tagname 폴백표**로 지원 근거가 아님. `controlFactory.createControlHash` 에도 항목 없음.
  - ※ `_websquare_/uiplugin/` 폴더 목록은 지연 로딩 플러그인만 담으므로(span/button/input 도 없음) 미탑재 판단 근거가 되지 않는다.
- `$p.dynamicCreate` 사용 불가 (동일 계열 `article`/`aside`/`section` 로 실측 확정):
  - `dynamicCreate(id,"header",'<header…>',parent)` → `Cannot read properties of undefined (reading 'then') at d.createControl`. XML 문자열을 주면 2번째 인자 pluginName 은 무시되고 노드 localName 으로 플러그인이 결정됨.
  - config `/WebSquare/dynamicCreate/parseChild/@value="true"` 강제 → `t.appendTo is not a function` 로 여전히 실패.
  - `dynamicCreate(id,"group",'<xf:group tagname="header">')` → 렌더는 되나 `class="w2group "` 기본 클래스가 붙어 본 API 의 `@spec`(기본 클래스 미추가)과 정면 배치 → 부적합.
- 정적 `<header>` 는 raw HTML pass-through 로 렌더되어 class 동작이 가이드와 일치 → DOM(`document.querySelector`) 기준 검증 유효.
- 따라서 UT_01 §7 정적 컴포넌트 배치 규칙 적용 (`wf_body_sample` 삭제, `grp_sample > grp_comp` 직접 배치, `comp_init`/`Target 재생성` 버튼 없음).
- `cm/gcc/common.xml`, `websquare/config.xml` 무수정. class 검증용 CSS 는 공용 `css/tc.css:45-46` 의 `.oddClass` / `.evenClass` 재사용(샘플 자체 style 블럭 없음).

### 구성 방식 (정적 배치 확정 근거)

- 배포 엔진(R1641)에 `header` uiplugin 미탑재. 번들 내 `header` 문자열은 `WebSquare.uiplugin.group.html5={article:"div",aside:"div",header:"div",...}` 뿐이며 이는 `group.toHTML()` 의 **IE6/7/8 전용 tagname 폴백표**로 지원 근거가 아님. `controlFactory.createControlHash` 미등록.
  - ※ `_websquare_/uiplugin/` 폴더 목록은 지연 로딩 플러그인만 담으므로(span/button/input 도 없음) 미탑재 판단 근거가 되지 않는다.
- `$p.dynamicCreate` 사용 불가 (동일 계열 `article`/`aside`/`section` 실측 확정) — 재시도 금지 3종:
  - `dynamicCreate(id,"header",'<header…>',parent)` → `Cannot read properties of undefined (reading 'then') at d.createControl`
  - config `/WebSquare/dynamicCreate/parseChild/@value="true"` 강제 → `t.appendTo is not a function`
  - `dynamicCreate(id,"group",'<xf:group tagname="header">')` → 렌더는 되나 `class="w2group "` 기본 클래스가 붙어 부적합
- **동적 생성 컴포넌트에는 원래 `mf_` 접두사가 붙지 않으므로**, `@spec`(Scope 미적용) 입증은 **정적 선언끼리 대비**해야만 성립 → 정적 `<header id="target1">`(→ `target1`) vs 정적 `w2:button id="btn_getId"`(→ `mf_btn_getId`) 로 구성.
- 따라서 UT_01 §7 정적 컴포넌트 배치 규칙 적용 (`wf_body_sample` 삭제, `grp_sample > grp_comp` 직접 배치, `comp_init`/`Target 재생성` 버튼 없음).
- `cm/gcc/common.xml`, `websquare/config.xml` 무수정.

### 실측 참고 (가이드 문구 대비 차이)

- **자동 부여 id 형식**: `wq_uuid_NN` (실측 `wq_uuid_11`). WebSquare 컴포넌트의 `mf_wq_uuid_NN` 과 달리 `mf_` 접두사가 없다. 번호는 엔진 전역 카운터라 **고정값이 아님** (TSQA 기대값으로 하드코딩 금지 → 접두사/패턴 매칭 권장).
- **`@spec` 예약어**: `id="style"`(속성명 예약어) 로 렌더해도 id 는 `style` 그대로 적용되고 **JS 오류 0건**. 가이드 원문이 "오류가 발생할 수 **있습니다**"(가능성) 표현이므로 결함으로 보지 않으며, `article`/`aside`/`section` 계열 실측과 동일하다. raw HTML pass-through 라 엔진 컨트롤 해시에 등록되지 않아 예약어 충돌 자체가 발생하지 않는 것으로 보임.
