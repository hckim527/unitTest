### 초기 HTML 시점 tabIndex 검출 방법 (설계 근거)

- 엔진 소스 `C:\ai_engine_bak\websquare\uiplugin\image\image.js` L880 (toHTML = 초기 HTML 생성)
  `var tabIndexStr = (this.options.accessibility) || (this.options.tabIndex == "") ? "" : "tabIndex='" + this.options.tabIndex + "'";`
  → accessibility=true 이면 tabIndex 를 초기 img 마크업에서 제외.
- 엔진 공통 `C:\ai_engine_bak\websquare\control\xfControl.js` `activate()` L1395~1404 (컴포넌트 초기화 완료 단계)
  `if (this.options.tabIndex) { ... this.render.tabIndex = this.options.tabIndex; }`
  → accessibility 값과 무관하게 초기화 완료 시점에 tabIndex 를 render 에 설정 (=@spec 의 "최종 동일").
- 따라서 최종 DOM 만 보면 true/false 구분 불가. 샘플은 `comp_init` 에서 dynamicCreate 직전에
  `MutationObserver(attributeFilter:["tabindex"], attributeOldValue:true)` 를 grp_comp(subtree) 에 걸어
  activate 단계의 tabindex 설정 시 **변경 전 값(oldValue)** 을 포착한다.
  - oldValue === null → 초기 HTML 에 tabIndex 미포함 (accessibility=true)
  - oldValue === "0"  → 초기 HTML 에 tabIndex 포함 (accessibility=false/미설정)

## 결과창 출력 보강 (2026-09-04)

기존 출력이 2줄(초기 HTML / 최종 tabIndex)뿐이라 validation 6항목을 출력만으로 판정할 수 없어 보강.
validation 문구는 변경하지 않았고, 초기 HTML 시점 검출 로직(MutationObserver `attributeOldValue`)도 그대로 유지.
1차 보강 후 사용자 요청으로 출력을 간소화(속성 name=value 덤프 / `[관측]` / `[참고]` 줄 제거) → 최종 **7줄**, 항목당 1줄.

### 검증 축이 하나뿐인 이유 (소스 확인)

- `uiplugin/image/image.js` 전체에서 `accessibility` 참조는 **880줄 1곳뿐** (toHTML). 초기 마크업에서 tabIndex 제외가 유일한 동작이며 aria-* / role / alt 등 별도 산출물 없음.
- `control/`, `engine/` 에 image 의 accessibility 를 읽는 코드 없음. 유일한 언급인 `engine/exprBindingManager.js:597` 은 Tier3(DOM 구조 결정 → dynamic 불가) **분류표**일 뿐 동작 아님.
- `control/xfControl.js activate() L1396~1404` 이 accessibility 무관하게 `render.tabIndex` 부여 → 렌더 완료 후 DOM 동일(= `@spec`).
- → 항목 1/3/4 의 "적용/미적용" 은 독립 관측 산출물이 없고, `@propval` 하위절(항목 2)의 초기 HTML tabIndex 포함 여부가 1/3/4 의 판정 근거를 겸한다.

### 최종 출력 구성 (7줄)

```
[설정] accessibility = {값} / tabIndex = {값}
[1] true 설정 시 웹접근성 기능 적용 : 적용 (초기 HTML tabIndex 미포함) | 해당 없음 (현재 X) | 판정 불가 (tabIndex 미설정)

[3] false 설정 시 미적용 : 미적용 (초기 HTML tabIndex 포함) | 해당 없음 (현재 X) | 판정 불가 (tabIndex 미설정)
[4] 미설정 시 미적용 : 미적용 (초기 HTML tabIndex 포함) | 해당 없음 (현재 X) | 판정 불가 (tabIndex 미설정)
[5] 렌더링 완료 후 설정 : 이전(X) / 현재(Y) -> 차이 없음 | 차이 있음 [이전 … / 현재 …]
[6] 최종 tabIndex : 이전(X) a / 현재(Y) b -> 동일 | 다름
```

- 항목 5 / 6 은 `scwin.gVar` prev* 슬롯(직전 재생성의 accessibility 설정값 / 최종 tabIndex / 속성 name=value 집합)과 대비 판정. prev 는 `comp_init` 진입 시 cur → prev 이관.
- 항목 5 는 속성 name=value 집합을 내부 비교하되 **일치 시 "차이 없음" 만 출력**(불일치 시에만 양쪽 값 노출)하여 간소화.
- 가드: prev 없음 → "비교 대상 없음", tabIndex 설정값 변경 → "비교 불가 (tabIndex 이전 X / 현재 Y)", prev·cur accessibility 동일 → 판정 뒤 "(accessibility 동일 값 비교)" 부기.
- 초기 HTML 판정 state: `none`(미포함→사후설정) / `has`(포함) / `unknown`(tabIndex 미설정으로 두 시점 모두 없음 → "판정 불가"). 기존 로직은 mutation 기록 0건이면 무조건 "미포함" 처리였으나, 최종 tabindex 존재 여부로 `has`/`unknown` 을 갈라 오판 제거.

### `@propval` 접두사 판단 근거

- `UT_01_생성.md` §2: "**`@propval` 기반 validation 은 해당 propval 의 값을 사전조건으로 문구 앞에 명시할 것**", 일반 값(default 아님)은 `"{값} 설정 시, ~"`.
- `title` 의 `@propval` 은 `<String>` 단일 항목이고 `@default` 가 비어 있어 default 분기(`"미설정 시, ~"` 2건 분리) 대상이 아니다 → `"{값} 설정 시"` 1건만 생성.
- 값이 열거형이 아니라 타입(String)이므로 같은 폴더 `image_P_alt_1.xml` 의 표기(`"문자열 값 설정 시, ~"`)를 따랐다.
- 참고: `image_P_ariaLabel_1.xml` 은 오버라이드 전(공통 tData 사용) 상태라 접두사 표기 사례로 쓰지 않았다.

### `@spec` 4 제외 사유

- "CSS 로 스타일링 할 수 없으며 웹접근성 향상 목적으로 적합하지 않습니다" 는 **관측 대상이 없는 부정·권고 서술**이다. title 은 브라우저 네이티브 툴팁이라 페이지 CSS 적용 대상 DOM 노드가 존재하지 않고("스타일링 불가"를 입증할 확인 수단 부재), "웹접근성 목적 부적합" 은 사용 지침이라 검증 트리거를 만들 수 없다.
