### 선행 과제 — `$c.gcm.createBasicSecret` 신규 추가

`cm/gcc/common.xml` 에 secret 계열 헬퍼가 없어 wrap 이 성립하지 않았다. `createBasicSearchBox` / `createBasicTextArea` 와 동일 형식으로 **추가만** 수행(기존 헬퍼 무수정), 삽입 위치는 `createEmptySearchBox` 와 `createBasicSelectBox` 사이.

```js
scwin.createBasicSecret = async function (cList='', eHandler='', cID='target1', cParent='') {
    if (cID === '') cID = 'target1';
    let grp_comp = scwin.getTestGroup(cParent);
    let strTarget = '';
    strTarget += '<xf:secret ' + scwin.strNameSpace + ' ' + cList + ' ' + eHandler + ' style="width:200px; height:40px;"></xf:secret>';
    scwin[cID] = await $p.dynamicCreate(cID, "secret", strTarget, grp_comp);
    scwin[cID].setValue("secret");
}
```

- 태그 `<xf:secret>` / plugin 명 `"secret"` : 엔진 소스 `uiplugin/secret/secret.js` 헤더(`@id secret`, `@namespaceURI http://www.w3.org/2002/xforms`) 확인.
- 크기 `width:200px; height:40px;` : 가이드 `@sample` 원문 값 채택.
- secret 은 `initValue` 속성이 없어(`@name` 목록에 부재) `setValue("secret")` 로 초기값 부여 — `createBasicSearchBox` / `createBasicTextArea` 와 동일 방식.
- `_wpack_/cm/gcc/common.js`, `_wpack_/sample/secret/secret_P_class_1.js` 는 Studio 가 자동 재컴파일 (수동 w-pack 미수행).

### MCP 실측 (port 50177, playwright 세션 3)

**렌더 상태 (con_disabled × 재생성)**

| con_disabled | 렌더된 outerHTML | class 문자열 | disabled 속성 | readonly 속성 |
|---|---|---|---|---|
| 미설정 | `<input id="mf_target1" class="w2input " type="password" style="width: 200px; height: 40px;">` | `w2input ` | false | false |
| true | `<input id="mf_target1" class="w2input w2input_disabled" type="password" disabled="disabled" style="width: 200px; height: 40px;">` | `w2input w2input_disabled` | true | false |

**상호작용 실측**

## secret_P_id_1.xml

`common_P/common_P_id_1.xml` 을 wframe 으로 감싸는 **`_P_id_1` 전용 wrap 패턴** (선례 25건 : `input/button/image/textbox/...`).
`con_ID` 입력창 · `Target 재생성` · `getID` 버튼 · 결과창은 공통 샘플이 소유한다.
다만 `common_P_id_1.xml` 의 validation 은 2건뿐이라 secret 가이드(`@tagversion 2.0`, `@spec` 4건)를 덮지 못하므로
**wrap 쪽에서 자체 `tData` 로 오버라이드**했다([[reference_common_wrap_tdata_override_pattern]]). 공통 샘플은 수정하지 않았다.

### `_P_id_1` 고유 구조 (다른 secret wrap 과 다른 점)

- `$c.gcm.createBasicSecret(cList)` 를 **쓰지 않는다.** 헬퍼는 `scwin[cID]` 에 객체를 담는데, 공통 샘플의 `getID` 버튼이
  `objParent.scwin.target1.getID()` 를 호출하므로 ID 를 바꾸면 `scwin.target1` 이 사라져 버튼이 깨진다.
  → 선례 25건과 동일하게 `scwin.target1 = await $p.dynamicCreate(cID, "secret", strTarget, grp_comp)` 직접 호출.
- wframe `style="height: 100%"` (class/disabled 계열의 `style=''` 아님) — 선례 일치.
- 태그 문자열은 `createBasicSecret` 과 동일하게 `<xf:secret class="secretClass" style="width:200px; height:40px;">` + `setValue("secret")`.
  `class="secretClass"` 는 `@spec3`(id Selector 대신 class Selector) 검증 수단.

| 파라미터 val (직전 입력값) 과 파라미터 id (mf_ 로 시작하는 렌더링 ID) … 반환 문자열이 onblur 줄의 입력값과 같은지 | validation (3)(4) 의 재서술 |
| 함수 실행 줄에 이어 출력되는 이벤트 발생 줄의 순서 | validation (5)(6) 의 재서술 — `[확인]` 의 "그 줄에 이어 출력되는 내용" 으로 흡수 |
| 사용자 정의 함수는 실행될 때마다 결과창에 함수 실행 줄을 남기므로 … | 같은 `[확인]` 줄의 앞부분과 중복 |

남긴 것은 운영 정보뿐이다 — 전제 설정값(초기값·조건 위치·함수의 반환 형태), 조작 절차(재생성 · 포커스 해제 · 버튼 · readOnly 조작), 관찰 지점(함수 실행 줄의 출현 여부 / password 라 값+글자 수 병기 / 값 누적 증가). 엔진 내부 구현·소스 경로·내부 메서드명은 포함하지 않았다.

**렌더 실측** : `<br/>` 2개 → **3줄**, `[전제]` 1회 / `[절차]` 1회 / `[확인]` 1회. console error 0건, 좌측 패널 validation 8항목, 대표 케이스(입력 후 포커스 해제) 출력 4줄 정상.

### secret_P_validator_1.xml — 라벨 최종본 (앞 절 라벨 기록을 대체)

바로 앞 `### secret_P_validator_1.xml — 라벨 머리표지 정리` 절에 적은 3줄 라벨은 머리표지 수는 맞았으나 `[전제]`·`[확인]` 줄에 함수 동작 설명·출력 형식 설명·값 누적 설명이 ` / ` 로 붙어 있었다. 추가 지적에 따라 그 부분까지 걷어낸 **아래가 최종 라벨**이다.

```
[전제] target1 은 Secret 컴포넌트(초기값 secret)이며 validator 와 readOnly 는 위 조건에서 선택합니다
[절차] 조건 선택 -> Target 재생성 -> target1 클릭하여 값 입력 후 바깥 영역 클릭 / setValue, validate 버튼도 각각 클릭 / readOnly=true 는 target1 클릭 후 바깥 영역 클릭
[확인] 결과창의 사용자 정의 함수 실행 줄 출현 여부와 파라미터 val, id / 이어지는 이벤트 줄의 순서와 입력값
```

**추가로 걷어낸 줄과 사유**

| 삭제한 내용 | 사유 |
|---|---|
| `con_validator 의 scwin.fn_validator 는 (id : 렌더링ID, val : 입력값) 형태의 문자열을 반환합니다` | 함수 동작 설명 — 결과창의 함수 실행 줄이 실물로 보여준다 |
| `Secret 은 password 라 값을 눈으로 셀 수 없어 값과 글자 수를 함께 출력하며` | 출력 형식 설명 (운영 정보가 아니라 샘플 구현 설명) |
| `반환 문자열이 다시 입력값이 되므로 포커스 해제를 반복하면 값이 길어집니다` | validation (4) 재서술 |
| `사용자 정의 함수 실행 줄이 나타나는지와 그 줄에 이어 출력되는 내용` (장황 표현) | `[확인]` 을 관찰 지점(줄 출현 여부 / 파라미터 / 이벤트 순서·입력값)만 남기도록 압축 |

라벨에서 뺀 내용 중 **판정에 필요한 사실은 모두 docs 에 이미 남아 있다** — password 라 값+글자 수를 병기한다는 구현 방침은 `02_검증.md` 의 "컴포넌트 함정 대응" 절에, 반환 문자열 누적으로 값이 길어지는 동작은 같은 파일 재실측 표의 케이스 2 에 기록되어 있다. 따라서 이번 삭제로 유실된 기록은 없다.
