**결함/불일치**

- **@spec1 불일치 (결함 의심)** — 가이드는 "메소드를 사용하여 비활성화(disabled) 상태를 변경한 경우엔 적용되지 않습니다" 라고 명시하나, **실제로는 `setColumnDisabled` / `setCellDisabled` / `setRowDisabled` 어느 경로로 비활성화해도 column 의 `disabledClass` 가 그대로 적용된다.** 초기 렌더 disabled Column(col1) 과 메소드로 비활성화한 Column(col3)·Cell(col4) 의 class 문자열이 완전히 동일해 구분되지 않음.
  - 엔진 근거 : `gridView/drawController.js:3921~3927` — `cellInfo.options.disabledClass != ""` 이면 `bDisabled` 만 보고 addClass 한다. `bDisabled`(3622~3646)는 `cellDisabledArr`(setCellDisabled) → `cellInfo.options.disabled`(setColumnDisabled) → `rowDisabledArr`(setRowDisabled) → `this.options.disabled` 순으로 해석되므로 **초기 렌더 여부를 전혀 구분하지 않는다.** `cellController.js:120~125` 도 동일.
  - 즉 가이드 문구가 엔진 구현과 맞지 않거나(문서 오기), 엔진이 렌더 시점 구분을 누락한 것. 어느 쪽이든 Jira 확인 대상.
- **참고(정상)** : grid 단위 기본값 `disabledClass: "w2grid_default_disabled"`(`gridView.js:409`) 가 column `disabledClass` 와 **항상 함께** 붙으므로 @spec2 / @propval\| 는 정상 동작. 해제 시 두 클래스 모두 removeClass 되어 @spec3 도 정상.
